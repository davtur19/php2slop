# Target-side reproduction: stock WordPress 7.1.3 + Apache 2.4.69 prefork + mod_php 8.4.24 (Debian 13.7)

Self-contained **setup** for the proven stock lab cell, runnable by an unprivileged
user (`netsec`) against **rootless Docker** on a Debian 13 host. It builds the
image, materialises the exact WordPress docroot, starts the target on
`127.0.0.1:8080`, and prints readiness checks.

> **Scope: setup only.** This script sends **no exploit traffic** and makes **no RCE
> claim**. It stops at a verified, running target. Any chain runner has to be
> executed separately, and nothing here asserts that the RCE reproduces.

> **Deployment:** this kit is published on the temporary branch
> `research/wp8424-setup`. See [`FETCH.md`](FETCH.md) for the exact
> `git fetch` / `git worktree add` / `./setup.sh up` sequence for the target host.
> `conf/` and `diag/` (§5) are generated by `setup.sh` at runtime and are not
> shipped in the branch. Use `RUN_DIR=<dir>` to keep runtime state out of the
> checkout.

## 2. Prerequisites

- Debian 13 host (validated on 13.7, x86_64).
- **Rootless Docker already configured for the invoking user** and usable **without
  sudo**: `docker info` succeeds and its `SecurityOptions` contains `rootless`.
  No host Apache, no rootful `/var/run/docker.sock`, no system service changes.
- `bash`, `curl`, `sha256sum` (coreutils), `docker` CLI.
- Outbound HTTPS to `registry-1.docker.io`, `deb.debian.org` (or
  `snapshot.debian.org`), and `wordpress.org` for the one-time build/artifact fetch.
- ~1.5 GB free disk (image ≈251 MB, ZIP 37 MB, docroot 110 MB, working space).
- `127.0.0.1:8080` free. The script refuses to start if the port is already serving;
  use `PORT=<free port>` to change it.

No file in `setup.sh` hardcodes a user name, home directory, or sudo. It was validated
on this host as uid 1000 with rootless Docker (`SecurityOptions: name=rootless`).

## 3. Run / stop

```bash
cd research_target/wp8424        # checkout of research/wp8424-setup
mkdir -p ~/wp8424-run
export RUN_DIR=~/wp8424-run      # optional: runtime state outside the checkout

./setup.sh up        # build if needed, (re)create container, run readiness checks
./setup.sh check     # re-run checks against the running container
./setup.sh status    # docker ps + HTTP status summary
./setup.sh logs      # container output + Apache error.log tail
./setup.sh shell     # shell inside the container
./setup.sh down      # stop and remove the container (image and files kept)
```

`up` is idempotent: it removes/recreates the container by name, and reuses the image
and docroot only after verifying package version, module hash, and docroot hashes.
The first run needs network for the image build; later runs are offline-capable.

### Overrides

| Variable | Default | Meaning |
|---|---|---|
| `PORT` | `8080` | host port bound on `127.0.0.1` |
| `NAME` | `wp8424-repro` | container name (safe to stop/recreate by name) |
| `IMAGE` | `wp8424-repro:8.4.24-deb13u1` | local image tag |
| `WITH_DIAG` | `1` | enable `/__repro/phpversion.php` alias (outside docroot) used for effective INI checks; `0` disables |
| `WITH_P2S` | `1` | reproduce the proven `p2s` LogFormat + CustomLog; `0` disables |
| `FORCE_BUILD` | `0` | `1` rebuilds the image from scratch |
| `BASE_IMAGE` | `debian@sha256:4c252754…b308` | pinned 13.7 base digest |
| `RUN_DIR` | directory of `setup.sh` | where `docroot/`, `artifacts/`, `logs/`, `out/` live |

Example for a host where 8080 is taken:

```bash
PORT=28081 ./setup.sh up
```

Stop by name at any time:

```bash
docker rm -f wp8424-repro
# or
./setup.sh down
```


as-is, so the setup can run offline once the ZIP and image are present.

## 7. Documented deltas vs. the proven container

These are deliberate, visible, and do not change the audited PHP/Apache cell:

1. **Image build.** The proven image was built by hand from `debian:13`, installing
   `apache2 procps gdb curl`, then local PHP 8.4.24 debs from `/debs`, and committed
   with `CMD sleep infinity`; Apache was started via `docker exec`. This script
   builds the same package set from pinned suites (or snapshot debs), commits with
   `CMD ["apache2ctl","-D","FOREGROUND"]`, and starts Apache as the container command.
   Behaviour is equivalent; the image ID is necessarily different. Identity is
   asserted by package versions, `libphp8.4.so` sha256 and `php.ini` md5, not by
   claiming a bit-identical image.
2. **gdb is not installed.** It was present in the proven image for post-mortem
   forensics only and is not needed to serve requests. This is the only package
   difference.
3. **`/__repro/phpversion.php`** (`WITH_DIAG=1`, default): an `Alias` to a file
   **outside** the docroot, used to sample effective INI values through the Apache
   SAPI. The CLI reports different values (`display_errors` empty,
   `output_buffering=0`), which is a known evidence-labeling trap. Disable with
   `WITH_DIAG=0`; the docroot itself is untouched either way.
4. **`p2s` logging** (`WITH_P2S=1`, default): the proven container carried a
   logging-only delta — `LogFormat "%P %{%s}t.%{usec_frac}t %m %U %>s %b %D" p2s`
   plus `CustomLog ${APACHE_LOG_DIR}/p2s-access.log p2s` in `000-default.conf`,
   generated from the stock file in the image. Disable with `WITH_P2S=0`.
5. **`/out` mode 0777** reproduces the proven writable proof directory; the earlier
   0755 variant failed proof writes under rootless uid mapping (container 33 →
   host 100032). `check` verifies writability as uid 33.

No database server, no `mysqli`, no `MaxRequestWorkers=1`, no `mod_unique_id`, and no
other tuning was added.

The snapshot tree `/home/davide/ailocal/php2slop` contains no binaries or archives.
Explicitly **not present** there, and how this setup handles it (no substitutes):

- **Docker image tarball / Dockerfile / build context** for the proven image

  from the pinned Debian base and pinned packages, then hash-verified (§7.1).
- **PHP 8.4.24 `.deb` files** (the proven build's `/debs`). Not shipped; downloaded
  from Debian 13 or snapshot.debian.org with the exact hashes in §6.
- **WordPress 7.1.3 archive.** Not shipped in `php2slop`; fetched from
  `wordpress.org` (hash-verified). A local reference copy exists at
  `/tmp/opencode/realapps/wordpress-7.1.3.zip` (same sha256) and may be copied to
  `artifacts/wordpress-7.1.3.zip` before running.
- **Database dump or schema.** None exists: the audited cell had no database and no
  `mysqli`, so nothing is invented here.
- **gdb** (present in the proven image). Intentionally omitted; see §7.2.

If any listed URL is unreachable or a hash mismatches, the script stops with a
`[FAIL]`/`missing artifact` message rather than falling back to a different version.

## 9. Limitations

- **No RCE claim.** No exploit request is sent by this script or by `check`.
- **No database.** WordPress cannot complete its install/bootstrap: `/` returns
  HTTP 500 ("missing the MySQL extension"). This matches the audited cell and is the
  expected, asserted state.
- **Rate figures are not reproduced here.** The documented rates (2/20 blind, 4/40
  lab-assisted) are properties of the runner and of a warmed target, not of this
  setup; treat them as such.
- **Direct mod_php only.** This reproduces the `apache2handler` cell; it does not
  model php-fpm, CGI, or other SAPIs.
- **Port 8080** is the documented default; on this validation host it was occupied
  by an unrelated local process, so the recorded evidence was produced on `28081`.
  The target host should use the default unless it has the same conflict.
