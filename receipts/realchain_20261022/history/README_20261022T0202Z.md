## 1. Real app and plugin pattern

The real application is WordPress with WooCommerce and the HexCoupon for WooCommerce plugin. The plugin method `HexCoupon\App\Core\Helpers\LoyaltyProgram\LoyaltyProgramHelpers::start_session()` calls `session_start()` at line 85 of `app/Core/Helpers/LoyaltyProgram/LoyaltyProgramHelpers.php`.

The lab adds two harness endpoints in the real tree.

1. `/wp-content/uploads/plant/hexplant.php` includes the real plugin trait and `LoyaltyProgramHelpers.php`, creates the real class without its constructor, and calls the real `start_session()` method. The endpoint lowers `memory_limit` to 2M with both `.user.ini` and `ini_set`, so the post RINIT session decode reaches OOM. The real plugin line 85 is the OOM site.
2. `/hextrigger.php` loads the full WordPress application through `wp-load.php`, then calls the same real plugin method through reflection. The exploit trigger is a multipart POST with `PHP_SESSION_UPLOAD_PROGRESS`, so PHP performs a pre RINIT session decode before WordPress runs. The plugin method sees the session already active and does not start a second session.

The FPM pool sets `session.save_path` to `/tmp/opencode/research/realchain_20261022T015900Z/www/wp-content/uploads/sessions`. That directory is writable by the FPM user and is served by nginx as `/wp-content/uploads/sessions/`. The attacker controls `PHPSESSID` through the cookie. The lab seeds the session file into the same web served writable upload directory; an arbitrary file write or upload primitive into that directory is the only external precondition.

## 2. Preconditions

1. PHP session serializer `php`, `session.use_strict_mode=0`, `session.upload_progress.enabled=1`, `session.upload_progress.cleanup=0`.
2. FPM pool memory limit high enough for WordPress and a plant endpoint that can lower the limit to 2M.
3. Attacker controlled `PHPSESSID` and a web served writable session file path.
4. A post RINIT OOM plant with a 64,946 byte session record leaves `basic_globals.unserialize` at level 1 with `data=P` and the worker alive.
5. The trigger multipart request must be the next request to that worker. RINIT resets stale state.
6. Heap geometry is stable inside one FPM master. gdb was used only to measure `P` and the second decode buffer before the final request. The final request has no gdb, no ptrace, no `setarch`.
