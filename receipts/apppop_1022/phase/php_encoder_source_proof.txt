PHP session `php` serializer: `|` key guard and failure-to-empty-write
=====================================================================
Claim: when session.serialize_handler=php, php_session_encode() rejects any
session key containing PS_DELIMITER ('|') (and, in most versions, the undef
marker '!'), and php_session_save_current_state() then writes a zero-length
string to the session store.  The upload-progress key is prefix+value, so any
value that starts a serialized object (x|O:...) makes the key contain '|' and
triggers this path.  No crafted object reaches the file.

The same else-branch write exists in 7.0/7.4/8.4 (empty zend_string) and as
s_write(..., "", 0) in 5.x.  PHP 8.5 adds the explicit warning string;
older versions fail silently from the caller's perspective, but the 0-byte result is
identical (measured below).
