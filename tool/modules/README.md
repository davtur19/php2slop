# tool/modules: one line per module

| module | what it does |
|---|---|
| `arm.py` | multipart `PHP_SESSION_UPLOAD_PROGRESS` request builder: arm/probe bodies, HTTP/1.1 framing helpers, 14-byte frozen-profile disclosure analyzer (consolidated from the pre-restructure `native-output-leak.py`; same functions and standalone CLI). |
| `native-output-leak-stock-arm.py` | author-provided reconstructed "STOCK" arm body (frozen-profile arm machinery record); consumed by the driver, keep as separate provenance module. |
| `compact-stock-tail.py` | author-provided reconstructed "COMPACT" rearm body + final forged multipart (the negative-`used_slots` controlled copy stage); consumed by `--step chain`. |
| `g2_chain.py` | G2/G6 FPM chain profiles for 8.5.10, 8.4.25, 8.1.34 and 7.4.33 (`addresses/g2_fpm_*.json`), plus the F12b realapps 8.5.10 `php`-handler profile (`addresses/g2_fpm_realapps_8510.json`, md5 `4ee099823b75e16ea36f93c71d57bfd8`, `zif_system` `0xa3c061`, `zif_passthru` `0xa3c074`), selected by version, binary md5 or path; and the offline `--step g2` record plan: `php_binary` (G2) or `zif_system`/`zif_passthru` (G6) decode, negative `used_slots` arithmetic, fake `php_unserialize_data` / `var_dtor_entries` placement, PS(serializer) slot, fake `zend_execute_data`, record bytes and self-checks. Targets are resolved by serializer entry name (`php_binary`), never `default_target`; the fake arg1 pointer is derived from the record-2 payload start Q; `zif_passthru` is read per profile (`+0x10` on the lab builds, `+0x13` on realapps), never synthesized. An overwrite is worker-local `.data` poison: it persists across non-crashing decodes and clears only on worker recycle; a crash respawn starts a pristine worker. The F12b `php`-format record is built by the receipt's `scripts/mkrec.py` (zif_system) or `mkrec_pt.py` (zif_passthru); the realapps profile carries `record_builder: php_binary_zif` and `--step g2` plans its entry-2 decode slot `0x22c54e0`, while the `php` slot `0x22c54c8` stays with the receipts. The F12b php-slot first clean `zif_passthru` survivor is the ASLR-off `f12b_passthru_20261021T224157Z` run (worker `1249940`, `WIKI_PASSTHRU`, HTTP 200); the static decode stays poisoned after the non-crashing passthru, so recycle the worker before normal session tests. Later ASLR-on runs are separate (`receipts/realchain_20261022/`, `receipts/realzif_entry2_1022/`). No transport and no address guessing. |
| `leak_stage.py` | mod_php leak stage, dry-only (`--step leak`): Set-Cookie PS(id) channel request shapes and the section C calibration plan; `leak_offset` is surfaced with its build binding (`addresses/apache_libphp.json`) and never guessed. |
| `producer.py` | facade over the CVE-109618 / CVE-109619 producer shape builders; mod_php producer TODO (missing module). |
| `producer_fpmwiki.py` | fpmwiki producer stage (`--step producer`): MediaWiki 1.46.2 anon-edit OOM, int N (5.7M receipt); sends to the supplied target, post_max_size ceiling guard. Promoted from the run_fpmwiki_20261021_173406 receipt. |
| `producer_modphp.py` | modphp producer stage (`--target modphp --step producer`): STOCK-arm body delegation (byte parity with the run_20261021T155303Z_armoom receipts, sha256-gated), int N = filename length ladder (262144/330000/400000 → alloc 266240/331776/401408), Cookie-transport sid (use_only_cookies=1), memory_limit knob pre-flight gate (absent/128M → refusal), sends to the supplied target. |
| `producer_unser.py` | unserialize OOM producer (master shape a, receipted 2M / 8M / 128M classes, sha256 receipt parity via `--verify-receipts`); sends to an explicit endpoint URL, dry() keeps the zero-socket byte builder, 128M class refused at the 8M post_max_size ceiling. |
| `producer_618.py` | CVE-2026-109618 staged multipart producer (heavy POST, OOM/stale machinery shape; inert forge default). Moved from `staged_618.py`. |
| `producer_619.py` | CVE-2026-109619 producer shape (149 x `t[]` reclaim records first → stale decoder state). Moved from `build_p1.py`. |
| `write_stage.py` | write stage, wired, dry-only (`--step write_stage`): builds the exact `attempt()`-shaped final multipart bytes via the documented `COMPACT.probe_body(...)` call and records them; no transport; the negative-`used_slots` math extraction (`stage_body()`) stays a NotImplementedError placeholder. |
| `profiles.py` | target + binary-profile registry: `BINARY_PROFILES` (per-build offsets) and `TARGETS` (wiki / wp live, modphp TODO missing module). |
